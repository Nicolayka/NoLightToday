## 📖 О проекте

**NoLightToday** — Telegram-бот на Python, который периодически проверяет
[страницу плановых работ](https://rosseti-lenenergo.ru/planned_work/)
Россети Ленэнерго, сравнивает свежие записи с вашими подписками и присылает
уведомления в группу или канал.

**Все настройки — в личке с ботом.** В группе или канале бот молчит и только
получает уведомления. Такой подход не засоряет чат и не мешает участникам.

Работает на Linux, macOS и Windows. Поддерживает группы, форумы с темами
и каналы.

Проект рассчитан на жителей Санкт-Петербурга и Ленинградской области,
которым важно заранее знать о предстоящих отключениях света.

## 🗓️ График проверок

По умолчанию бот проверяет сайт **раз в час**, 24/7. При старте запускается
немедленная проверка, чтобы не ждать первого интервала.

| Событие | Когда выполняется |
|---|---|
| Первая проверка сайта | Сразу после запуска бота |
| Последующие проверки | Каждые `CHECK_INTERVAL` секунд (по умолчанию 3600) |
| Автопроверка НП | Сразу после добавления подписки пользователем |
| Отправка уведомления в чат | В момент обнаружения новой записи |
| Обновление кэша `outage_cache` | На каждой проверке |
| Пометка «уже отправлено» | Сразу после успешной отправки сообщения |

Интервал легко поменять в `src/config.py` или через `.env`:

```dotenv
CHECK_INTERVAL=1800    # 30 минут
CHECK_INTERVAL=3600    # 1 час (по умолчанию)
CHECK_INTERVAL=7200    # 2 часа
```

> ⚠️ Не рекомендуется ставить интервал меньше 30 минут — это создаёт
> лишнюю нагрузку на сайт Россети и может привести к временной блокировке
> вашего IP.

2. **Узнайте свой Telegram ID** у [@userinfobot](https://t.me/userinfobot).

   ```bash
   git clone https://github.com/Nicolayka/NoLightToday.git
   cd NoLightToday
   ```

4. **Создайте `.env`** из шаблона и заполните:

   ```dotenv
   BOT_TOKEN=123456789:AA...ваш_токен
   ADMIN_IDS=123456789

   # Опционально: прокси для Telegram (если сервер в РФ и провайдер

   ```

5. **Установите зависимости и запустите** — по инструкции для вашей ОС ниже.

### 🐧 Debian / Ubuntu (установка как служба)

Для сервера рекомендуется установка через `install.sh` — бот станет
systemd-службой, будет автоматически перезапускаться и стартовать при
загрузке системы.

```bash
cd /home/NoLightToday
sudo bash scripts/install.sh
```

Скрипт сам:
- поставит нужный Python (3.11 / 3.12 / 3.13),
- создаст системного пользователя `nolighttoday`,
- скопирует проект в `/opt/nolighttoday`,
- создаст venv и поставит зависимости,
- настроит `/etc/systemd/system/nolighttoday.service`,
- запустит службу.

После установки:

```bash
sudo nano /opt/nolighttoday/.env     # вписать токен и ADMIN_IDS
sudo systemctl restart nolighttoday
sudo systemctl status nolighttoday
sudo tail -f /opt/nolighttoday/logs/stdout.log
```

Удалить:

```bash
sudo bash scripts/uninstall.sh             # с подтверждением
sudo bash scripts/uninstall.sh --keep-data # сохранить БД и .env
```

## 🎛 Использование

### Как это работает

1. **Добавьте бота** в группу или канал.
2. Бот **ничего не пишет в чат** — все настройки в личке.
3. Тому, кто добавил, приходит **личное сообщение** с кнопкой «⚙️ Настроить».
4. В личке выбираете чат → настраиваете подписки, приоритеты, темы.
5. Уведомления приходят **в группу или канал** (в выбранную тему, если форум).

### Добавление бота в группу

1. Добавьте бота в группу.
2. Дайте ему право **отправлять сообщения**.
3. **Отключите Privacy Mode** через @BotFather: `/setprivacy` → выберите бота → **Disable**. Без этого бот **не увидит** обычный текст в группе.
4. **Перезайдите бота в группу** (удалите → добавьте снова), чтобы Telegram применил Privacy Mode.
5. Откройте личку с ботом → `/start` → выберите группу в списке.

Если бот уже был в группе до обновления кода — отправьте ему `/start` в личке, чтобы обновить список чатов.

### Добавление бота в канал

1. Добавьте бота в канал как **администратора** с правом **публикации**.
2. В личке с ботом `/start` → появится канал в списке.
3. Настройте подписки.

### Ручной ввод населённого пункта

Если в списке нет нужного адреса (например, «СНТ Фауна», «Петровское»,
«Ломоносовский») — нажмите **➕ Добавить свой НП** и отправьте название
следующим сообщением. Бот ищет совпадения сразу в трёх полях:
«Район / Населённый пункт», «Адрес» и «Населённый пункт».

**После добавления бот сразу:**
- сохраняет подписку,
- парсит сайт именно по этому НП,
- обновляет кэш,
- рассылает свежие уведомления,
- показывает итог: сколько записей найдено и на какие даты.

Это позволяет не ждать планового часа.

> 💡 Можно вводить часть названия: «Фауна» найдёт и «тер. СНТ Фауна»,
> и «д Петровское тер. СНТ Фауна». Регистр не важен.

### Темы форума (подтемы)

**Проблема:** Telegram Bot API **не даёт списка существующих тем форума**.
Бот узнаёт о теме только в момент её создания, и только если он уже в группе.

**Решение 1.** Создайте тему в группе-форуме **при работающем боте** — он её
запомнит автоматически. Либо переименуйте существующую — тоже сработает.

**Решение 2.** Если автоматика не сработала — используйте команду `/topic`:

1. Зайдите в нужную тему форума.
2. Отправьте сообщение: `/topic Отключения`
3. Бот сохранит тему с указанным названием.

Повторите для каждой темы. После этого она появится в разделе
«🎯 Куда писать (подтемы)».

### Логика «главного» НП

Допустим, вы подписаны на **Гатчину** и **Всеволожск**, и у Гатчины приоритет
выше (в списке «🏆 Приоритет» она сверху). На 15 марта есть отключения
в обоих НП.

**Что произойдёт:** бот пришлёт **одно** сообщение — по Гатчине, а про
отключение во Всеволожске напишет короткой припиской. Полный список по обоим
НП доступен в разделе **📅 Отключения → 15.03.2026**.

Это защищает чат от спама, когда на один день выпадает сразу много записей.

## 💾 Работа с базой данных

Все данные — в одном файле `data/bot_data.db` (SQLite).

### Таблицы

**`subscriptions`** — подписки чата на НП:

| id | chat_id | locality | priority |
|----|---------|----------|----------|
| 1  | -1001234567890 | Гатчина | 1 |
| 2  | -1001234567890 | Всеволожск | 2 |

**`sent_notifications`** — что уже отправлено (защита от дублей):

| chat_id | outage_id | sent_at |
|---------|-----------|---------|
| -100… | `a1b2c3…` | 2026-03-14 08:00:11 |

**`outage_cache`** — кэш всех спарсенных записей:

| outage_id | date_key | locality | payload (JSON) | fetched_at |
|---|---|---|---|---|

**`chats`** — список групп и каналов, куда добавлен бот:

| chat_id | title | added_at | updated_at |
|---|---|---|---|
| -1001234567890 | Моя группа | 2026-09-30 12:00 | 2026-09-30 12:00 |

**`awaiting_input`** — флаг «ждём ввод названия НП»:

| user_id | chat_id | kind | created_at |
|---|---|---|---|
| 140769359 | -1001234567890 | `locality` | 2026-09-30 14:03 |

> `awaiting_input` заменяет FSM: когда вы нажали «➕ Добавить свой НП», бот
> ставит флаг для **вашего user_id** и ждёт следующего текстового сообщения.
> Это переживает перезапуск бота.

**`chat_settings`** — выбранная тема форума для уведомлений:

| chat_id | thread_id | updated_at |
|---|---|---|
| -1001234567890 | 5 | 2026-09-30 15:00 |

**`forum_topics`** — известные темы форума (сохранённые автоматически или через `/topic`):

| chat_id | thread_id | name | updated_at |
|---|---|---|---|
| -1001234567890 | 5 | Отключения | 2026-09-30 15:00 |

### Резервная копия


При следующем запуске он создастся заново.

## 🌐 Прокси для Telegram

### Зачем это нужно

На **российских VPS** провайдеры часто блокируют `api.telegram.org`
по **SNI** — DPI видит домен в TLS-хендшейке и рвёт соединение. При этом
по IP-адресу Telegram доступен, но бот не может с ним работать напрямую.

**Решение — SOCKS5 или HTTP-прокси** вне России. С российского VPS
весь трафик к Telegram идёт через прокси, а сайт Россети — напрямую.

### Настройка

1. Получите прокси, например у **Proxyline**, **Proxy6**, **Proxy-Seller**.
2. Пропишите в `.env`:

   ```dotenv
   TELEGRAM_PROXY=socks5://user:password@host:port
   ```

   Или `http://user:password@host:port`.

3. Убедитесь, что установлен `aiohttp-socks`:

   ```bash
   /opt/nolighttoday/.venv/bin/pip install aiohttp-socks
   ```

4. Перезапустите службу:

   ```bash
   sudo systemctl restart nolighttoday
   ```

В логе появится:

```
[INFO] nolighttoday: Telegram через прокси: host:port
[INFO] aiogram.dispatcher: Run polling for bot @NoLightToday_bot
```

Без прокси (например, на зарубежном VPS) переменную можно не задавать —
бот будет работать напрямую.

## 🪟 Автозапуск на Windows

### Вариант A — Планировщик задач (Task Scheduler)

1. Откройте **Task Scheduler** (`taskschd.msc`).
2. **Create Task** → вкладка **General**:
   - Name: `NoLightToday`
   - ✅ Run with highest privileges
3. Вкладка **Triggers** → **New…** → **At log on**.
4. Вкладка **Actions** → **New…**:
   - Action: `Start a program`
   - Program/script: `C:\путь\до\nolighttoday\scripts\run.bat`
   - Start in: `C:\путь\до\nolighttoday`
5. Вкладка **Settings**:
   - ✅ If the task fails, restart every **1 minute**, up to **3** times.
   - ❌ Stop the task if it runs longer than… *(снять галочку)*.
6. **OK**.

### Вариант B — NSSM (служба Windows)

Скачайте [NSSM](https://nssm.cc/download), распакуйте `nssm.exe`
в `C:\Tools\nssm\`. В **cmd от имени администратора**:

```cmd
C:\Tools\nssm\nssm.exe install NoLightToday "C:\путь\до\nolighttoday\.venv\Scripts\python.exe" "-m src"
C:\Tools\nssm\nssm.exe set NoLightToday AppDirectory "C:\путь\до\nolighttoday"
C:\Tools\nssm\nssm.exe set NoLightToday AppStdout "C:\путь\до\nolighttoday\logs\stdout.log"
C:\Tools\nssm\nssm.exe set NoLightToday AppStderr "C:\путь\до\nolighttoday\logs\stderr.log"
C:\Tools\nssm\nssm.exe set NoLightToday AppEnvironmentExtra "PYTHONIOENCODING=utf-8" "PYTHONUTF8=1"
C:\Tools\nssm\nssm.exe set NoLightToday Start SERVICE_AUTO_START
C:\Tools\nssm\nssm.exe start NoLightToday
```

Управление:

```cmd
nssm.exe status  NoLightToday
nssm.exe restart NoLightToday
nssm.exe stop    NoLightToday
nssm.exe remove  NoLightToday confirm
```

## ⚙️ Кастомизация

### Свой список населённых пунктов

Отредактируйте `LOCALITIES` в `src/config.py`. Бот перерисует меню подписок
по этому списку. Это лишь **быстрые кнопки** — пользователь всё равно может
добавить любой НП вручную через «➕ Добавить свой НП».

### Несколько администраторов

В `.env`:

```dotenv
ADMIN_IDS=111111111,222222222,333333333
```

Все они смогут настраивать бота в чатах, где являются админами.

### Проверка только определённого района

В `src/parser.py` после парсинга строки можно фильтровать по `region` / `district`:

```python
records = [r for r in records if "Гатчинский" in r["district"]]
```

### Отправка уведомлений не в группу, а в личку

Замените `chat_id` в таблице `subscriptions` на личный ID пользователя.
Бот отправит сообщение туда же, куда и подписка.

## 🧪 Тестирование парсера

Перед первым запуском бота полезно убедиться, что парсер достаёт данные:

```cmd
.venv\Scripts\python.exe -c "from src.parser import parse_outages; data = parse_outages(street='СНТ Фауна', max_pages=1); print('Найдено:', len(data)); [print(' •', r['district'], '|', r['address'][:60], '|', r['start']) for r in data]"
```

Ожидаемый вывод:

```
[parser] street='СНТ Фауна' стр.1: 2 записей
Найдено: 2
 • р-н Ломоносовский | тер. СНТ Фауна д Петровское тер. ДНП Петровское | 30-09-2026 09:00
 • р-н Ломоносовский | д Петровское тер. СНТ Фауна Петровская слобода… | 25-09-2026 09:00
```

Если вывод пустой — проверьте **индексы колонок** в `src/parser.py`, открыв
HTML таблицы на сайте через F12 → Elements. На странице три `<table>`:
форма фильтра, данные, служебная. Нам нужна вторая — с классом `tableous_facts`.

Запуск юнит-тестов:

```bash
pytest -q
```

## 🛠 Частые проблемы

| Симптом | Причина / решение |
|---|---|
| **Бот не отвечает в группе** | Это нормально! В группе бот молчит. Все команды — в личке. |
| **TelegramConflictError** | Где-то работает второй экземпляр бота. Проверьте `ps aux \| grep python`, старый VPS, локальный ПК. |
| **TelegramNetworkError: timeout** на RU VPS | SNI-блокировка. Настройте `TELEGRAM_PROXY`. |
| **HTTP 403 от Россети на зарубежном VPS** | Гео-блокировка. Нужен российский прокси или RU VPS. |
| **SSL CERTIFICATE_VERIFY_FAILED от Россети** | В `parser.py` уже стоит `verify=False` — сайт подписан сертификатом Минцифры. Не убирайте эту опцию. |
| **Бот не отвечает на `/start`** | Ваш ID не в `ADMIN_IDS`. Узнайте через [@userinfobot](https://t.me/userinfobot). |
| **Бот молчит в группе на обычный текст** | Включён Privacy Mode. Отключите через @BotFather → `/setprivacy` → Disable, и перезайдите бота в группу. |
| **Не видит темы форума** | Telegram Bot API не отдаёт список тем. Создайте тему при боте или используйте `/topic <название>` внутри темы. |
| **Парсер возвращает `[]`** | Изменилась вёрстка таблицы — поправьте индексы колонок в `src/parser.py`. |
| **`pydantic-core` не собирается на Python 3.13+** | Используйте `aiogram>=3.15` (актуальная версия в `pyproject.toml`). Не откатывайтесь на `3.4.1`. |
| **Уведомления не приходят** | Бот не добавлен в группу или у него нет прав на отправку. Проверьте `SELECT chat_id FROM subscriptions`. |
| **Дубли уведомлений** | Проверьте таблицу `sent_notifications` и уникальный индекс. |
| **«📅 Отключения» показывает пусто** | Кэш ещё не заполнен или по вашим НП нет отключений на эту дату. |
| 🪟 **`python не является внутренней командой`** | Python не в PATH. Переустановите с галочкой **Add python.exe to PATH**. |
| 🪟 **Русские буквы в консоли — «кракозябры»** | Выполните `chcp 65001` перед запуском. В `run.bat` уже включено. |
| 🪟 **PowerShell блокирует `run.ps1`** | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| 🪟 **Windows Defender блокирует сеть** | Добавьте `.venv\Scripts\python.exe` в исключения. |
| 🪟 **Файл БД в OneDrive / Dropbox повреждён** | Не храните `bot_data.db` в облачной синхронизации. |
